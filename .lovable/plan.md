# تطوير قسم الشحن

ملاحظة سريعة: خطأ `src/lib/utils.ts(8,7)` قديم ومش موجود دلوقتي — الملف 6 أسطر بس وفحص الأنواع بيعدي نضيف.

## الوضع الحالي (بعد الفحص)

- `/shipping`: 3 تبويبات (الشحنات / المناديب / المناطق) + بحث + تغيير حالة بقيود state machine على مستوى الداتابيز.
- `/shipping/day`: ملخص يومي بقيمة الشحنات والمدفوع والمعلّق.
- `/shipping/rescue`: الشحنات والطلبات المتعثرة مع واتساب واتصال.
- الشحنة فيها: مندوب، منطقة، رقم تتبع، حالة، توقيتات كل حالة، مستلم/تليفون/عنوان.
- **غير موجود**: تكلفة شحن فعلية على الشحنة، مبلغ تحصيل عند الاستلام (COD) وتسويته، بوليصة/ليبل للطباعة، عمليات جماعية، تقييم أداء المناديب، تايم لاين مرئي للشحنة.

## المقترح — 4 مراحل

### 1) الفلوس داخل الشحن (الأهم)
- إضافة أعمدة للشحنة: تكلفة الشحن الفعلية، مبلغ التحصيل (COD)، حالة تحصيل الفلوس من المندوب (لم يُحصّل / محصّل / مُسوّى).
- عند "تم التوصيل": تسجيل تلقائي لدفعة الفاتورة + مصروف شحن، وربط التسوية بالصندوق.
- كارت "مستحقات المناديب": كل مندوب وعليه كام محصّل لسه ما اتسلّمش، وزر تسوية.

### 2) تشغيل يومي أسرع
- تحديد متعدد للشحنات (checkbox) + تغيير حالة جماعي، وتعيين مندوب جماعي.
- طباعة **بوليصة شحن** PDF لكل شحنة (باركود رقم التتبع، بيانات المستلم، مبلغ التحصيل) وطباعة **مانيفست** للمندوب بكل شحنات اليوم.
- فلاتر أعلى الصفحة: الحالة، المندوب، المنطقة، الفترة الزمنية — بشريط بحث ملتصق زي باقي الأقسام.

### 3) متابعة الشحنة والعميل
- Drawer تفاصيل الشحنة: تايم لاين مرئي (انتظار → تجهيز → شحن → تسليم) بالتوقيتات ومين غيّر الحالة، مع الفاتورة والمنتجات.
- زر واتساب جاهز برسالة فيها رقم التتبع ولينك صفحة تتبع الطلب العامة.
- تنبيه "متأخرة" أوتوماتيك حسب مدة التسليم المتوقعة للمنطقة، وربطه بصفحة الإنقاذ.

### 4) تحليلات الشحن
- كروت KPI: نسبة التسليم الناجح، نسبة المرتجع، متوسط أيام التسليم، متوسط تكلفة الشحنة.
- جدول أداء المناديب (شحنات / نسبة نجاح / متوسط أيام / تكلفة) ومخطط أداء المناطق.

## تفاصيل تقنية

- Migration جديدة على `public.shipments`: `shipping_cost numeric default 0`، `cod_amount numeric default 0`، `collection_status` (enum نصي مع CHECK)، مع GRANTs موجودة أصلًا للجدول.
- توسعة `update_storefront_shipment_status` لتسجيل الدفعة والمصروف داخل نفس المعاملة بدل منطق واجهة.
- تحديث `Shipment` interface + mapper في `src/lib/store.ts`، وإضافة `settleCarrierCollections`.
- البوليصة والمانيفست عبر `src/lib/pdf-doc.ts` والباركود عبر `src/lib/barcode.ts` (موجودين).
- الواجهة داخل `src/pages/Shipping.tsx` بنفس لغة التصميم (BezelCard / Reveal / sticky-search-bar).
